# Ctrl for Apple platforms

- **`Ctrl/`**: the macOS menu bar app (SwiftUI `MenuBarExtra` and `Settings`, AppKit where SwiftUI has no API).
- **`CtrlKit/`**: a Swift package the iOS app will reuse. It holds the clip summary model, the Keychain `SecretStore`, and the pasteboard adapters that sit between `NSPasteboard` and `ctrl-core`.
- **`project.yml`**: the XcodeGen spec. `Ctrl.xcodeproj` is generated and not checked in.

## Building

```bash
scripts/build-xcframework.sh --macos-only   # from the repo root: core → bindings/apple
cd apple
xcodegen generate
open Ctrl.xcodeproj                         # or: xcodebuild -scheme Ctrl build
(cd CtrlKit && swift test)
```

Requires Xcode 16 or later. The app targets macOS 15 and builds in the Swift 6 language mode with complete concurrency checking.

## How the app works

| | |
|---|---|
| **Watching** | `ClipboardSync` polls `NSPasteboard.general.changeCount` every 250 ms on a background queue. On a change, `PasteboardReader` reads every representation that has a canonical format, converts TIFF to PNG, attaches a thumbnail to images, and hands the clip to `CtrlNode.publish`. Copied files go by path, and the core reads them only when a peer pastes. |
| **Privacy** | Items carrying `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` are skipped before any data is read. They are never sent and never enter history. |
| **Receiving** | `PasteboardWriter` writes inline data directly. Large data is promised through `NSPasteboardItemDataProvider`, and large files through an `NSFilePromiseProvider` that downloads on its own operation queue, so pasting a 2 GB file into Finder never blocks the main thread. |
| **Loop prevention** | Everything Ctrl writes carries the private `app.ctrl.origin` type, and the watcher never sends an item that has it. |
| **Launch at login** | `SMAppService.mainApp`, toggled in Settings → General. The app is an `LSUIElement`, so it has no Dock icon. |

## Debug launch arguments

Debug builds accept a few arguments for screenshots and performance checks. None of them start the core or touch the network.

```bash
Ctrl.app/Contents/MacOS/Ctrl -CtrlDemo YES                           # canned clips and devices
Ctrl.app/Contents/MacOS/Ctrl -CtrlDemo YES -CtrlDemoCount 500        # ...500 of them
Ctrl.app/Contents/MacOS/Ctrl -CtrlDemo YES -CtrlSnapshot ~/Desktop   # write popover PNGs and quit
```

## Known gaps

- Copying an item from history puts it on this Mac's pasteboard but doesn't send it to other devices again.
- Folders aren't synced yet. The core sends regular files only.
- Large non-file data, such as an image over 256 KB, is fetched on the main thread when an app reads it, because AppKit's data provider API is synchronous. That takes tens of milliseconds on a LAN.
- Received files over 256 KB go on the pasteboard as file promises only. Apps that read `public.file-url` and don't accept promises can't paste them yet.
